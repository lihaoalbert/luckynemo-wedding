## 一、现状盘点

**内容**：108 模板 / 20 系列 / 6 分组（index.json v3 已上线）。

- 8 个新系列（hyd/sak/muh/lig/spk/han/min/hor）= 9 变体，「九宫格」卖点成立；
- 12 个 mk 老系列（教堂/中式/江南/花海/夜景/森林/港风×2/街拍/正装/海边/山野）**只有 3 变体**，「整组 9 张」对这些系列名不副实；
- 人群结构偏科：情侣 13 系列，女单 4，男单 3——而女生是写真主力消费人群。

**链路**（小程序 moka 页现状）：hero 文案 → 6 分组横滑 tab → 系列卡双列 → 弹层九宫格 → 整组/单张生成。

**体验问题清单**（按用户动线排）：

1. **首屏即全量列表**：没有主推、没有热度信号，新用户面对 20 个系列不知从何选起（选择瘫痪）。
2. **分类是风格语言不是任务语言**：「花海浪漫/森林与原野」是摄影师视角；备婚用户的心智是「领证官宣/婚纱照/旅拍/个人写真」。
3. **系列详情是弹层、信息太薄**：没有大图、没有「生成后效果预期」、没有价格前置，点「整组生成」前用户心里没底。
4. **9 变体卖点对 mk 系列不成立**（实际 3 张），按钮文案与内容不一致会伤信任。
5. **无搜索/收藏/浏览历史**：系列到 30+ 后找不到、回不来。
6. **没有运营位**：上新、节日专题、限时没有承载位置，内容运营无从发力。
7. **生成完即结束**：缺「发朋友圈长这样」的预览钩子，传播闭环断在最后一步。

## 二、调研结论（外部参照）

来源与完整笔记见文末附录；五条可直接用的：

1. **模板即预期**（妙鸭相机核心心法）：把 prompt 封装成「明确的预期效果」，用户点之前就知道会得到什么。封面图必须让用户能脑补出「换成我」的样子——大图、人脸清晰、构图完整，不要用氛围感空镜当封面。
2. **九宫格是传播语言**：「晒满 9 张」是朋友圈自发刚需，妙鸭刷屏期用户原话就是"九宫格来自妙鸭"。「一个系列 = 一条朋友圈九宫格」是我们与妙鸭（单张为主）的差异化，要在 UI 和分享文案里明说。
3. **分类用场景/节点语言**：婚摄机构按「风格+目的地+价位」组织套系；对备婚用户，「领证/婚纱照/旅拍」比「森系/复古」更接近搜索心智。风格词降级为标签。
4. **上新节奏 = 复购引擎**（海马体打法）："不是你想要，而是它创造的场景让你想去拍"。节日/人生节点专题（520、七夕、国庆、领证纪念日）是被验证的复购触发器，比 UI 优化重要。
5. **决策成本压缩**：价格前置透明 + 「不满意可重做」承诺 + before/after 效果示例，是看到→生成转化的三大件。妙鸭 9.9 对标海马体 399 的话术，我们 4 元/张天然适用（"4 元 vs 影楼 399"）。

## 三、内容规划原则（v4）

1. **系列即九宫格**：9 变体才称「系列」并给「一键九宫格」CTA；不足 9 的补齐，或明示「3 张精选」。
2. **一级入口按人生节点，二级按风格分组**：节点（领证/婚纱/旅拍/写真）是任务入口，6 大风格分组保留为浏览维度，两者是同一批系列的两种索引。
3. **封面规范**：大场景+双人（或单人）人脸清晰、竖构图 3:4；禁用空镜/背影/小人脸。每系列封面=最佳的一张，不一定是 01。
4. **每个系列自带传播件**：九宫格拼图 + 朋友圈预览，生成完成页即分享页。
5. **上新日历驱动内容生产**（见 §六），淡季储备、节点前 2-4 周上线专题。

## 四、信息架构方案（v4，对应 demo 三屏）

```
发现首页（S1）
 ├── 搜索框（场景/风格关键词，系列≤30 时可先做占位+筛选）
 ├── 主推轮播（1-3 个运营位：节日限定/本周主推/上新）
 ├── 人生节点入口（领证官宣/婚纱大片/旅拍游记/个人写真 → 筛选系列集）
 ├── 本周热门（横滑大卡 + "N 人拍过" 社交证明）
 └── 全部系列（6 风格分组 tab + 双列系列卡，卡上带「◫ 9张」角标）

系列详情页（S2，独立页替代弹层）
 ├── 顶部大图（封面变体，可滑）
 ├── 系列名 + 标签（人数/场景/季节）+ 一句话卖点
 ├── 数据条（9 张成片 / 出镜人数 / ≈时长 / N 人拍过）
 ├── 3×3 九宫格预览（点开全屏左右滑，直接对应朋友圈 9 格）
 ├── 「都搭配好了」成分表（场景/服装/妆容/姿势，沿用 components 字段）
 └── 底部固定 CTA：价格前置（36币整组/单张4币）+「只拍单张」+「一键九宫格」

生成与结果（S3）
 ├── 进度页：x/9 逐张点亮（已有，保留）
 └── 结果页：九宫格 → 「发到朋友圈长这样」mock 预览 → 模板vs成片对比 → 一键保存全部/分享海报
```

**数据层改动（index.json v4 草案）**：series 增加 `moments[]`（节点归属，可多挂）、`tags[]`、`hot`（拍过人数，先运营填写后接真实统计）、`cover`（指定封面变体）、`status`（normal/new/limited）；groups 层不变。前端无 v4 字段时回退现有渲染，平滑升级。

## 七、指标口径（埋点建议）

漏斗：发现页曝光 → 系列卡点击（点击率）→ 详情页 CTA 点击（发起率）→ 生成完成（完成率）→ 保存/分享（采纳率）。
另记：整组 vs 单张比例、节点入口 vs 分组的点击率对比、复拍间隔。AI 产品的激活不是注册而是「第一次拿到可用结果」，中段看「采纳（保存/分享）」不看生成数。

## 九、决策记录（2026-08-07 已拍板）

1. **详情页独立页**：✅ 接受多一级跳转，按 demo 独立页方案实施。
2. **mk 系列补齐 9 变体**：✅ 补。先用 **MiniMax 生图出占位稿**快速凑齐 9 格，上线前用 Seedream 逐张重出替换（⚠️ 占位稿必须打标——MiniMax 生图 2026-08-01 因效果差已下架，占位与正式版画风会不一致，不能让占位稿直接见客）。
3. **节点入口命名**：✅ 就用 领证官宣 / 婚纱大片 / 旅拍游记 / 个人写真 4 个。
4. **热门「N 人拍过」**：✅ 运营基础数字 + 真实计数叠加（`hot` = base + 真实生成次数，series 上配 base 值）。
5. 收藏功能：✅ 现在就做（按 openid 存 mp_favs，me 页加入口）。
6. 搜索：✅ 现在就做（客户端过滤 title/tags/分组名，不动后端）。
7. 定价呈现：「36币整组」vs「36元整组」——币的概念在详情页怎么表达最不虚？（待定，demo 暂用「币」）

**demo 交互补充（2026-08-07）**：「只拍单张」进入选片模式——九宫格每格右上角出现相册式选中圆圈（空心→金色✓），可多选，底部 CTA 实时变「生成选中 N 张 →」+ 价格 N×4币联动；非选片模式点格子仍是看大图。
