## 一、市场调研（增量部分）

### 1.1 婚礼筹备 AI 竞品格局

| 竞品 | 形态 | 已有 AI 能力 | 与 Nemo Studio 的关系 |
|---|---|---|---|
| **婚礼纪**（C 端平台） | App + 商家市场 | AI 小犀顾问、AI 婚策方案生成、AI 试纱、AI 智能客服（2025 已在用，结婚垂类智能体加速中） | 最强参照系。但它是**撮合平台**：AI 用于导购和导流，不做深度定制创作，没有"每对客户一个项目文件夹"的生产概念 |
| **weddingee 婚嫁AI局**（B 端素材库） | 订阅制网站 | 分镜库、全案库、提案素材 | 卖模板素材，无生成能力、无人物一致性。验证了我们"预置剧本库"的方向，但它的内容我们不可用（版权） |
| **到喜啦 / 婚礼时光** | 传统 O2O | 无实质 AI 生成能力 | 不构成竞争 |
| **海外 Zola / Joy / The Knot** | 筹备 SaaS |  checklist、请柬、registry；AI 仅文案润色 | 无影像生成能力。海外也没有"AI 婚礼创作智能体" |
| **淘宝/点评 AI 婚纱照作坊** | 手工作坊 ×100+ | 人工跑图，无流程无标准 | 已被我们的标准化管线碾压（见首单与样片） |

**判断**：婚礼筹备全流程 AI（筹备+试衣+影像）目前只有婚礼纪在做，且做在"导购层"；**"创作层"——为每对新人深度定制影像资产的智能体——没有人做**。Nemo Studio 的差异化不在功能列表，在于：项目文件夹承载的单客资产、试衣→定妆→照相馆→短片的**人物一致性主线**、以及已经跑通的生产管线。

### 1.2 试衣技术现状（【试衣间】的底座）

- **阿里 OutfitAnyone（百炼 Model Studio API）**：商业化 API，支持整身/上装/下装/局部替换，按次计费，可直接采购，免去自研。（[阿里云文档](https://help.aliyun.com/zh/model-studio/outfitanyone/)）
- **开源路线**：IDM-VTON、Kolors Virtual Try-On（可图换装）可自部署，效果好但需要 GPU 运维，与工作室"无 GPU 运维"原则冲突，**不建议自建**。
- **Seedream 参考图换装**：我们已验证的 reference_image 模式可以做"人设 + 服装描述"的定妆照，零新增依赖，但服装还原精度弱于专用试衣模型。
- **建议**：M1 用 Seedream 定妆照（服装以"服装平铺图/样板图"作 reference_image），精度不够再接 OutfitAnyone API，两条路都留在 adapter 后面。

### 1.3 插件形态参照

对话 + 独立渲染窗口的双界面形态（对话做输入与修改，独立窗口做结果呈现）已是创作类智能体的主流交互（Canvas/Artifacts 模式），用户教育成本低。输入端用网页（微信可转发）符合备婚人群习惯——我们已有 `/story/`（问卷）与 `/upload/`（素材）两个线上入口，可直接复用扩展。

## 二、Nemo Studio 智能体规划

### 2.1 一句话定义

**Nemo Studio 是婚庆创作智能体插件：以"每对新人一个项目文件夹"为核心，驱动试衣、婚纱照、爱情短片的创作全流程；对话界面做交互，独立窗口做呈现。**

设计原则：
1. **项目文件夹是唯一事实源**（Single Source of Truth）——所有参数、素材、资产、产出都在文件夹里，智能体只读写它
2. **人物一致性是主线**——定妆照是所有下游创作的锚
3. **用户深度参与但不增加负担**——关键节点给用户"选择"而不是"填空"
4. **先有的管线不重复造**——script/video/photo/voice/asset_pipeline 全部复用

### 2.2 项目文件夹 Schema（单客档案）

```
couples/<订单号>_<新郎>&<新娘>/
├── profile.json          # 基础参数：姓名、婚期、联系方式、风格偏好、授权状态
├── intake/               # 用户输入：问卷原文、自拍/生活照（按拍摄指引）、声音样本
├── identity/             # 身份资产：正脸特写、三视图、方舟 asset:// 登记（assets_registry.json）
├── wardrobe/             # 试衣间：选择的服装组合 + 定妆照（新郎/新娘各 N 套）
├── scenes/               # 照相馆：选中的场景资产图
├── photos/               # 婚纱照产出（含品控记录）
├── film/                 # 短片：story_intake.txt、storyboard.json、clips、narration、bgm、成片
└── delivery/             # 交付物 + manifest.json + aimeta sidecar
```

`profile.json` 存授权状态（人脸授权、声音克隆授权），合规检查在每次生成前强制读取。

### 2.3 资产库：「霓裳阁」

命名：**霓裳阁**（取"霓裳羽衣"，婚庆氛围足，且与 LuckyNemo 的 N 呼应）。

结构（每类 ≥100 款样板，Seedream 批量生成 + 人工品控入库）：

```
霓裳阁/
├── 婚纱/      # 主纱（缎面/蕾丝/鱼尾/A字/蓬裙…）、出门纱、敬酒服
├── 礼服/      # 新郎西装（黑/灰/藏青/塔士多）、中式长袍、秀禾男装
├── 中式/      # 秀禾服、龙凤褂、旗袍、凤冠霞帔
├── 配饰/      # 头纱、头饰、珠宝、胸花、捧花
├── 鞋履/      # 婚鞋（水晶鞋/缎面/中式绣鞋）
└── 套装/      # 官方搭配组合（设计师预搭，一键成套）
```

- 每件资产：样板图（平铺/人台）+ metadata（风格标签、色系、适合身材、推荐搭配 ID）
- **套装（一键搭配）**：由我们按"主纱+头纱+配饰+鞋"预搭 20-30 套主题（如"晨曦缎光""红金囍嫁""森系轻纱"），选择困难用户的默认路径
- 入库即带品控：生成 → 图墙筛 → 不合格重抽，与现有照片品控同流程

### 2.4 模块一：【试衣间】

- **一键搭配**：从套装库选主题 → 生成双人定妆照
- **自由挑选**：按类型逐件选（婚纱/礼服/配饰/鞋），智能体给搭配建议（色系/风格冲突提示）
- **定妆照**：以 identity 资产为人物锚 + 选中服装为参考，生成标准定妆照（正面站姿，灰底）
- **定妆照是硬通货**：写入 `wardrobe/`，后续婚纱照与短片的人物+服装一致性都引用它
- 网页端可微信转发：用户在手机上完成挑选（复用上传页框架做选择页）

### 2.5 模块二：【照相馆】

- 场景库走"**微剧情场景**"设计：不是"海边/草坪/教堂"的空场景，而是带叙事的一瞬——"初雪便利店的暖光""图书馆同一排书架两端""天台那碗泡面的热气"。静态照片也要有故事感
- 场景库预生成（同短片场景资产的做法），每个场景配一句"剧情引子"供用户选择时感受
- 产出：选场景 × 选定妆照 → 婚纱照（沿用 photo_pipeline 风格模板 + reference 模式）
- 品控：图墙 + 防分身约束 + 重拍纪律（已有）

### 2.6 模块三：【爱情短片】

- **剧本共创**（质量感的来源）：
  1. 用户填故事问卷（已有 `/story/`）
  2. 智能体出**故事梗概**（不是分镜）让用户确认"这是我们的故事"
  3. 用户可对话修改细节（"我们其实是在图书馆认识的"）
  4. 确认后生成正式分镜（剧本模板库 ×6 起骨架，M3 填细节）
  5. 关键镜头给用户看首帧/参考图再进生成
- **标准化制作流程（SOP，已从首单+样片沉淀）**：
  问卷 → 梗概确认 → 分镜 → 场景/服装资产 → 定妆照锚定 → reference_image 生成 → 重拍纪律品控（五判词/单变量/预算）→ 克隆旁白 → BGM → 精剪 → delivery 合规交付
- 每一步落盘到项目文件夹，任何一步可回退重做

### 2.8 智能体架构

### 2.9 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| **M1 试衣间** | 霓裳阁首批 100+（婚纱 40/礼服 30/配饰 20/鞋 10）+ 套装 20 套；定妆照生成；`/wardrobe/` 选择页 | 一对虚拟新人完成 3 套定妆照 |
| **M2 照相馆** | 微剧情场景库首批 30 个；`/scenes/` 选择页；婚纱照产出 | 一组"讲故事"的婚纱照 demo |
| **M3 短片** | 剧本共创流程（梗概确认环节）；全 SOP 跑通 | 用共创流程重做一支样片，对比旧版 |
| **M4 后续** | 请柬/物料设计、婚庆流程设计（排期/流程表） | 另立项 |

### 2.10 主要风险

1. **试衣精度**：Seedream 换装对复杂款（蕾丝/凤冠）还原可能不足 → 预留 OutfitAnyone API adapter
2. **婚礼纪跟进**：平台方若下沉做创作层，有流量优势 → 我们的护城河是单客项目文件夹深度与创作质量，且我们是 B 端工具不与其抢 C 端
3. **资产版权**：霓裳阁全部自生成，禁用任何品牌款（vera wang 等）做参考
4. **合规**：定妆照/婚纱照/短片交付统一走 delivery（已强制）；人脸授权状态进 profile.json，未授权不生成
5. **成本**：霓裳阁首批建设约 150 张图 ≈ 100 元算力，一次性投入；单客边际成本与现有测算一致
